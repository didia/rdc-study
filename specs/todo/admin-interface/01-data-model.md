# 01 — Data Model

Postgres (Supabase). All objects live in `public`, created by SQL migrations in `supabase/migrations/`. Tables are
introduced by the phase that needs them; Phase 1 creates everything marked **P1**.

## 1. Design principles

1. **A person is not a request.** The same person comes back (admission → CAQ → visa); the old tracker had 595 rows for
   555 distinct emails. `clients` 1—N `service_requests`.
2. **Status is a first-class lookup, history is append-only.** Current status lives on the request; every change is
   an immutable `request_events` row (replaces the old Journal tab and "Dernière mise à jour").
3. **Catalogue stays in git.** `service_type` and `package_slug` are validated text, not FKs (see
   [00 §4](./00-decision-and-architecture.md)).
4. **Normalised vocabularies.** Countries and statuses are controlled lists — the old spreadsheet's free text is the
   cautionary tale.
5. **Default-deny RLS; invariants in the database** (triggers) rather than only in UI code.

## 2. Roles

`staff_role` enum: `admin` (everything, user management, delete), `agent` (create/update clients & requests, notes,
payments), `mentor` (Phase 3: read/update only requests assigned to them), `viewer` (read-only).

## 3. Schema (P1 unless noted)

```sql
create extension if not exists citext;
create extension if not exists pg_trgm;

create type staff_role as enum ('admin','agent','mentor','viewer');

create table staff_profiles (
  id          uuid primary key references auth.users(id) on delete cascade,
  full_name   text not null,
  role        staff_role not null default 'viewer',
  active      boolean not null default true,
  whatsapp    text,                       -- used by Phase 2 templates
  created_at  timestamptz not null default now()
);

-- Lookup: editable labels/order/colour; transitions are enforced in app + trigger (see §5)
create table request_statuses (
  code        text primary key,           -- 'new','contacted',...
  label_fr    text not null,
  stage       text not null check (stage in ('open','won','lost')),
  sort_order  int  not null,
  color       text,
  is_active   boolean not null default true
);

create table clients (
  id              uuid primary key default gen_random_uuid(),
  first_name      text not null,
  last_name       text not null,
  email           citext,                  -- nullable: manual entries (WhatsApp/phone) may not have one yet
  phone           text,                    -- raw as entered
  phone_e164      text,                    -- normalised when parseable (used for dedupe + wa.me)
  origin_country  text,                    -- canonical label from the controlled list
  preferred_channel text check (preferred_channel in ('whatsapp','email')),
  notes           text,
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);
create unique index clients_email_uq on clients (email) where email is not null;
create index clients_phone_idx on clients (phone_e164);
create index clients_name_trgm on clients using gin ((first_name || ' ' || last_name) gin_trgm_ops);

create sequence request_ref_seq;

create table service_requests (
  id                uuid primary key default gen_random_uuid(),
  reference         text unique not null default
                      'RDC-' || to_char(now(),'YYYY') || '-' || lpad(nextval('request_ref_seq')::text, 4, '0'),
  client_id         uuid not null references clients(id) on delete restrict,
  service_type      text not null,         -- assistance|consultation|verification|verification-et-lettre|information
  destination_country text,                -- canonical label ('Canada','Belgique','Chypre du Nord',...)
  package_slug      text,                  -- 'canada/visa', 'belgique/equivalence', ... (nullable for manual entries)
  status            text not null default 'new' references request_statuses(code),
  status_reason     text,                  -- free text, e.g. why failed / no follow-up
  has_dispute       boolean not null default false,      -- replaces the old "Litiges" column
  source            text not null check (source in ('website_form','manual','whatsapp','referral')),
  source_url        text,                  -- the page the form was submitted from (today's `link`)
  original_message  text,                  -- sentence generated by the site form (kept verbatim)
  form_answers      jsonb not null default '{}',   -- structured form state: hasAdmission, isGoingToQuebec, ...
  assigned_to       uuid references staff_profiles(id),
  next_follow_up_at timestamptz,           -- P2 UI; column created in P1 to avoid a later migration
  submitted_at      timestamptz not null default now(),    -- "Date de demande"
  last_activity_at  timestamptz not null default now(),    -- replaces "Dernière mise à jour"
  closed_at         timestamptz,           -- set by trigger when the request enters a 'lost' status (P3: also 'completed'); see §5
  idempotency_key   text unique,           -- intake double-submit protection
  quoted_price_cents int,                  -- price at submission, set server-side from service_prices (never from the browser)
  quoted_currency   text default 'USD',
  displayed_price_cents int,               -- what the visitor's page showed; differs from quoted only if the price changed mid-session
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);
create index sr_status_idx   on service_requests (status);
create index sr_assigned_idx on service_requests (assigned_to);
create index sr_submitted_idx on service_requests (submitted_at desc);
create index sr_followup_idx on service_requests (next_follow_up_at) where next_follow_up_at is not null;
create index sr_client_idx   on service_requests (client_id);

-- Editable prices (see phase 1 §1C "Pricing"): one row per service type
create table service_prices (
  service_type  text primary key,          -- same codes as service_requests.service_type
  amount_cents  int not null check (amount_cents >= 0),
  currency      text not null default 'USD',
  updated_at    timestamptz not null default now(),
  updated_by    uuid references staff_profiles(id)
);
create table service_price_history (        -- append-only, written by trigger on service_prices
  id            bigint generated always as identity primary key,
  service_type  text not null,
  old_amount_cents int, new_amount_cents int not null,
  currency      text not null,
  reason        text,
  changed_by    uuid references staff_profiles(id),
  changed_at    timestamptz not null default now()
);

create table request_events (               -- append-only history / Journal
  id          bigint generated always as identity primary key,
  request_id  uuid not null references service_requests(id) on delete cascade,
  type        text not null check (type in
                ('created','status_change','note','contact_attempt','assignment','field_change','payment','document')),
  from_status text,
  to_status   text,
  channel     text check (channel in ('whatsapp','email','phone','office','other')),
  body        text,                        -- note text / reason
  metadata    jsonb not null default '{}',
  actor_id    uuid references staff_profiles(id),   -- null = system / public intake
  created_at  timestamptz not null default now()
);
create index re_request_idx on request_events (request_id, created_at desc);
```

  id uuid primary key default gen_random_uuid(),

  kind text not null check (kind in ('contract','receipt','client_document','deliverable','other')),
  storage_path text not null,              -- private bucket `request-docs`
  file_name text not null, mime_type text, size_bytes int,
  uploaded_by uuid references staff_profiles(id),

## 4. Seed data

`request_statuses` (code · label · stage · order). Labels reuse the old tracker's vocabulary.

| code | label_fr | stage | order |
|------|----------|-------|-------|
| `new` | Nouvelle demande | open | 10 |
| `contacted` | Contact initial | open | 20 |
| `in_discussion` | En discussion | open | 30 |
| `awaiting_client` | En attente du client | open | 40 |
| `follow_up` | Relancé | open | 50 |
| `office_visit` | Va passer au bureau | open | 60 |
| `awaiting_payment` | En attente de paiement | open | 70 |
| `deposit_paid` | Acompte payé | won | 80 |
| `paid` | Payé intégralement | won | 90 |
| `in_progress` | Accompagnement en cours | won | 100 |
| `completed` | Terminé | won | 110 |
| `lost_failed` | Échec | lost | 120 |
| `lost_no_response` | Sans suite | lost | 130 |

`won` = a paying client; the funnel's "conversion" is "reached any `won` status". `paid`, `in_progress`, `completed`
are not in the old tracker (it stopped at "Acompte payé"/"Réussi") but exist so Phase 3 has somewhere to go; they are
hidden in the UI until Phase 3 (`is_active=false`) so Phase 1 stays faithful to the current process.

`service_prices` is seeded with: `information` 0, `consultation` 30, `verification` 150, `verification-et-lettre` 200,
**`assistance` 400**. The `information` row is locked to 0 (check in the admin action).

Controlled lists live in code (`lib/admin/vocab.ts`), not tables, because they change rarely and are shared with the form:
- `ORIGIN_COUNTRIES` — the 44 entries of the old workbook's "Pays dorigine" list (+ "Autre"), which already matches the audience.
- `DESTINATION_COUNTRIES` — Belgique, Canada, Chypre du Nord, France, Inde, Tunisie, États-Unis, + Roumanie (new guide)
  and any added through `src/components/AssistanceForm/destination-countries.js`; one source of truth imported by the form
  and the console.
- `SERVICE_TYPES` — extends `src/constants/assistance.js` (`information`, `assistance`, `consultation`, `verification`,
  `verification-et-lettre`). The slug-to-title lookup for packages is a single function (`lib/admin/packages.ts`) used by both the form and the console.

## 5. Triggers & functions (invariants)

1. **`set_updated_at()`** on `clients`, `service_requests`.
2. **`log_request_changes()` (AFTER INSERT/UPDATE on `service_requests`)** — inserts `request_events`:
   - insert → `created` (actor = `auth.uid()` or null),
   - status changed → `status_change` with `from_status`/`to_status`/reason (`status_reason`),
   - `assigned_to` changed → `assignment`,
   - and bumps `last_activity_at`; sets `closed_at` when moving into a `lost` status (and in P3, `completed`), clears it on reopen.
   Because this is a trigger, **no code path can change status without history**.
3. **`touch_request_on_event()`** (AFTER INSERT on `request_events`) → updates `service_requests.last_activity_at`.
4. **`staff_role()`** `security definer`, `stable` — returns the caller's role if `staff_profiles.active`, else `null`.
5. **Transition rules** are advisory in the UI (default: any open status → any status; `lost_*` → `new`/`contacted` requires
   "reopen" with a reason). Hard rules in the DB would fight real-life WhatsApp conversations; revisit if data shows abuse.
6. **`log_price_change()`** (AFTER UPDATE on `service_prices`) — inserts a `service_price_history` row (old → new, actor, optional reason
   passed via `set_config('app.price_reason', …, true)` by the admin action) and refreshes `updated_at/updated_by`.
7. **`submit_service_request()`** reads the current `service_prices` row for the requested service and stores it in
   `quoted_price_cents` (the browser-supplied `displayedPriceCents` is stored separately, never trusted).
8. **`merge_clients(keep uuid, drop uuid)`** (P2) — moves requests, copies missing fields, logs events, deletes `drop`.

## 6. Row Level Security

All tables: `alter table … enable row level security;` and **no policy for `anon`**.

| Table | select | insert | update | delete |
|-------|--------|--------|--------|--------|
| `staff_profiles` | any active staff (own row at minimum) | `admin` | `admin` (self may edit own `full_name`/`whatsapp`) | `admin` |
| `request_statuses`, `lost_reasons` | any active staff | `admin` | `admin` | `admin` |
| `service_prices` | any active staff | `admin` | `admin` | **none** |
| `service_price_history` | any active staff | trigger only | **none** | **none** |
| `clients` | active staff; `mentor` only if they have an assigned request for that client | `admin`,`agent` | `admin`,`agent` | `admin` |
| `service_requests` | `admin`,`agent`,`viewer` all; `mentor` only `mentor_id = auth.uid()` (P3) | `admin`,`agent` | `admin`,`agent`; `mentor` limited to status/notes on assigned (P3) | `admin` |
| `request_events` | follows parent request visibility | `admin`,`agent`,`mentor`(assigned) with `actor_id = auth.uid()` | **none** | **none** |
| `message_templates`, `saved_views` | active staff (views: owner or shared) | `admin` (views: owner) | same | same |
| `payments`, `request_documents` | `admin`,`agent`, `mentor`(assigned, documents only) | `admin`,`agent` | `admin` (void) | **none** (void instead) |

Storage bucket `request-docs` (P3): private; object policies mirror `request_documents` access via a join on
`storage_path`; downloads through short-lived signed URLs created server-side.

Public intake bypasses RLS via the service-role key but **only inside** `app/api/requests/route.ts`, which calls a single
`security definer` SQL function `submit_service_request(payload jsonb)` (upsert client by email → insert request →
event) so the route cannot be tricked into arbitrary writes and the logic is testable in SQL.

## 7. pgTAP tests (`supabase/tests/*.sql`, run in CI)

- `anon` cannot select/insert/update/delete any table; cannot execute `submit_service_request` (service role only).
- `viewer` can select, cannot insert/update; inactive staff see nothing.
- `agent` can insert/update requests, cannot delete; cannot update or delete `request_events`.
- Changing `service_requests.status` writes exactly one `status_change` event with the actor.
- Only `admin` can update `service_prices`; every update writes one `service_price_history` row; history is not updatable/deletable.
- `submit_service_request()` stores the DB price as `quoted_price_cents` even if the payload claims another price.
- Same email submitted twice → one `clients` row, two requests; same `idempotency_key` → one request.
- (P3) `mentor` sees only assigned requests and their clients/events/documents.
